Managed Lesser hosting with governance, trust, billing, and soul identity built in.

Architecture

Single-origin control plane, isolated tenant runtime.

The host stack is AWS CDK managed and deployed through the AppTheory contract. Public traffic lands at one CloudFront distribution; tenant workloads run outside the host account boundary in per-slug managed accounts.

01

CloudFront entry

Static web assets and API paths share a first-party origin to preserve a strict no-inline CSP posture.

02

Control and trust APIs

/api/*, /auth/*, and /setup/* route to the control-plane API; /.well-known/* and /attestations* route to the trust API.

03

State and queues

DynamoDB, S3, SQS, KMS, SSM, and Secrets Manager back jobs, attestations, release receipts, billing state, and operational evidence.

04

Managed account runner

The provisioning worker invokes CodeBuild to deploy verified Lesser and Body releases into the target tenant account.

Non-negotiables

The page is simple; the platform is high-trust.

These constraints shape every production change in the repository.

Multi-tenant isolation

Each managed instance has its own AWS account and delegated DNS zone. Host avoids tenant content and stores only control-plane metadata.

Consumer release verification

Lesser and lesser-body artifacts are downloaded, manifest-checked, and SHA-256 verified before any managed deployment proceeds.

Trust API rigor

Instance API keys are raw only at presentation time; host persists and compares hashes. Attestations are signed and publicly verifiable.

On-chain care

Soul and TipSplitter operations use Solidity tests, linting, Slither, Sepolia-first deploys, and Safe-ready mainnet governance.

Governance evidence

gov-infra/ verifiers are deterministic, fail closed, and emit evidence rather than silently weakening the rubric.

AGPL and CSP discipline

No proprietary blobs, no secret material in git, no inline scripts/styles, and no third-party script dependency for operator surfaces.

Maintainer loop

Validate the surfaces that match the change.

For production changes, the normal path is branch, review, CI, lab deploy and soak, then authorized live deploy. CDK deploys use theory app up --stage <lab|live> --execute; do not timeout CloudFormation.
